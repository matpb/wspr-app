Changelog

Every user-facing change to Wspr. Versions before 5.1.0 predate this changelog — see the full history on GitHub Releases.

5.7.0 — August 12, 2026

Wspr now tells you when it is recording, and stops pasting filler text when you did not say anything.

Added

  • Start and stop sounds. A short, bright click when recording starts and a softer, lower one when it stops, so you know the recording state without looking at the screen. The two are far apart in pitch, rising for start and falling for stop, so you can tell them apart without thinking about it. Cancelling plays the stop sound too, so a hotkey that did not register is never confused with one that did. The sounds are synthesized rather than sampled: there are no audio files to ship, and the volume slider is a true gain rather than a preset. On by default, with an on/off toggle, a volume slider and a Test button under Settings → General. The start sound plays before Wspr dims your system audio, so dimming or muting can no longer swallow it.
  • Empty recordings are discarded instead of transcribed. Starting and stopping without speaking used to hand Whisper pure silence, which it answers with invented filler like “Thank you for watching.” Wspr now checks the audio itself for speech and throws the recording away if it finds none, telling you it did. The check adapts to your own room: it compares against the recording's own noise floor rather than a fixed level, so it works in a quiet office and a cafe alike, and it deliberately errs toward keeping a recording. When the start sound is on it ignores the head of the recording, so the sound picked up by your microphone cannot fool it; with the sound off it weighs the whole recording, so a single short word still gets through. On by default, and switchable off under Settings → General.

Fixed

  • Linux: raising a system notification could kill the app. Any message Wspr showed you from a recording, such as telling you the selected model is not downloaded, went through a notification library in a way that is unsafe from inside the app's async runtime, and took the whole app down with it. Linux now raises notifications on its own thread.

5.6.0 — July 31, 2026

Adds Large v3 Turbo — Large-class accuracy at roughly Small's speed — plus a set of licence reliability fixes.

Added

  • New model: Large v3 Turbo. A 1.6 GB model that reaches Large v3 accuracy at roughly Small's speed. On a 45-second recording it transcribes in 1.16 s against Large v3's 3.40 s and Medium's 1.93 s (measured warm on an RTX 4060 Ti with Vulkan), and it loads in about half Large v3's time. It is now the best speed-to-accuracy trade in the list, and it beats Medium on both. Turbo is a separate download in Settings → Models; your current model stays selected until you choose it.

Fixed

  • Pro is no longer lost when the system credential store can't be read. If your Keychain, wallet or Credential Manager was locked or unavailable when Wspr started — common on Linux desktops with a locked login keyring, and on headless or remote sessions — Wspr treated your licence as absent and quietly dropped you to the free tier. It now keeps Pro active and shows Wspr Pro (unverified) in the tray menu so you know to check on it.
  • A refreshed licence check can no longer fail on a full disk. Wspr re-records the date each time it validates; if that write failed, the whole successful check was thrown away and Pro was lost for that session.
  • A finished file transcription is never discarded. If Wspr could not write the entry to its history, it threw away the completed transcript along with it — losing hours of work to a bookkeeping error. The transcript is now always returned.
  • A clock skewed into the future no longer confuses offline licence checks.

Changed

  • Selecting Large v3 Turbo and then downgrading to 5.5.0 or earlier resets the active model to Base, because older versions do not recognise the new value. Custom vocabulary and every other setting are preserved — just re-select your model after a downgrade.

5.5.0 — July 30, 2026

Fixes a defect that silently destroyed parts of long transcriptions, plus the language setting that never worked.

Fixed

  • Long recordings no longer get stuck repeating a phrase. Transcribing a long file could make Whisper latch onto a sentence and repeat it dozens or hundreds of times, replacing minutes of real speech — in the worst case we found, 75% of a transcript. Whisper feeds each 30-second window its own previous output as context, so one repeat could reinforce itself for the rest of the file. Audio is now decoded in bounded spans, so a repetition can no longer propagate. Short dictations were never affected.
  • "Auto" language detection now actually detects. The Language setting's default "Auto-detect" silently decoded everything as English, so non-English recordings were transcribed as though they were English — which also made the repetition problem more likely. Auto-detect now works, and the language list has grown from 9 to 27.
  • A damaged settings file no longer wipes your settings. Any unreadable field in the settings file reset everything — hotkeys, custom vocabulary, rewrite styles — and immediately overwrote the file. Wspr now salvages every field it can read and keeps a backup of the original.
  • Custom vocabulary now applies to a whole recording. It previously faded out after the first few minutes of a long file. It is now re-applied throughout.
  • Clearer errors for files that can't be read — an unreadable or corrupt media file now explains what went wrong instead of showing an exit code.

Added

  • Progress and cancellation for file transcription. File jobs show a live percentage and can be cancelled mid-run instead of being uninterruptible. A cancelled job doesn't count against your usage.
  • Automatic repetition guard. If a degenerate repetition ever slips through, Wspr collapses it, marks the spot inline, and keeps the original text in history rather than silently shipping the junk.

Changed

  • Decoding now uses Whisper's own default candidate count, which improves its ability to recover from a bad patch of audio. Slightly slower only when a recovery is actually needed.
  • Segment boundaries on long files may differ slightly from 5.4.0. Timestamps remain continuous; SRT output may split lines at different points.

5.4.0 — July 12, 2026

A codebase-wide quality-and-hardening pass (internal audit). The focus is reliability, error visibility, and safer releases.

Fixed

  • Hardened error handling throughout the engine — silent failures and several reachable crash paths now surface a clear notification instead of failing quietly or aborting.
  • Transcribing a WAV file that isn't 16 kHz mono (e.g. a normal 44.1/48 kHz recording) now converts it properly instead of producing garbage output.
  • Tightened the recording state machine and webview/download handling for more predictable behaviour under edge cases (rapid hotkey presses, device disconnects mid-recording, very long recordings).

Added

  • Errors during dictation ("No speech detected", transcription failures) now show a system notification, so they're visible even with no Wspr window open.
  • Log files under the app data directory (logs/), making problems diagnosable after the fact.

Changed

  • Overhauled the release pipeline for safer, more reproducible builds: the macOS build now refuses to sign or ship a partial/stale app bundle, the updater manifest is verified and published as a confirmed step (so a release can't be silently stranded), signing keys are no longer exposed on process command lines, and the Windows cross-compile toolchain is tracked in-repo (with a reproducible fetch step for the Vulkan SDK). Build docs were rewritten to match the actual build system.

5.3.1 — June 26, 2026

Fixed

  • Linux AppImage: crash when opening the window on Wayland. On modern Wayland sessions with a recent Mesa (e.g. Fedora 44 / Mesa 26), clicking the tray icon to open the window crashed instantly with Could not create default EGL display: EGL_BAD_PARAMETER — while hotkey dictation kept working, since that path never creates a window. The AppImage was shipping its own older Wayland client libraries, and the version mismatch against the host's Mesa broke EGL initialisation in the WebKit renderer. Those libraries are now stripped from the AppImage so the host's are used, which is where Wayland client libraries are meant to come from (thanks Nat for the detailed report).
  • Linux AppImage: SIGABRT on launch on GLib 2.80+ distros. The bundled GLib stack (2.72) shadowed the host's newer GLib while the host's tray libraries expected GLib 2.80+ symbols, aborting the app on startup on Fedora 40+ and Ubuntu 24.04+. The bundled GLib closure is now unbundled so the host's GLib is used.

5.3.0 — June 18, 2026

Fixed

  • Linux: glibc-portable bundles and working Wayland global hotkey. Linux release bundles are now built against an older glibc so they launch on current LTS distros, and the global dictation hotkey works correctly under Wayland.
  • Settings dropdowns unreadable in light mode. Forced a dark color-scheme so the Settings dropdown menus stay legible regardless of the system light/dark preference.
  • Windows: removed the msvcp140.dll dependency. The MSVC C runtime is now statically linked, so Wspr no longer fails to start on machines without the Visual C++ redistributable installed.

5.2.0 — May 6, 2026

Added

  • Custom rewrite styles (Pro). Settings → Rewrite now has a "Custom styles" section where Pro users can create, edit, and delete their own rewrite prompts. Each custom style appears in the Default style dropdown alongside the built-ins (Minimal, Professional, Concise). Custom styles persist across launches and are picked up automatically by the rewrite hotkey and the recording-pill style picker.

    This feature was advertised on the pricing page since v5.0 but the UI hadn't been wired up during the Rust+Tauri rewrite — fixed now (thanks Frank Drewett for the report).

5.1.3 — May 5, 2026

Fixed

  • macOS: menu-bar-only behaviour. Wspr now installs as an Accessory app (no Dock icon), and the Settings window reliably comes to the front when invoked from the tray menu — matching the behaviour of other menu-bar apps like Rectangle and Bartender.

5.1.2 — May 4, 2026

Fixed

  • Linux Wayland (KDE Plasma 6, GNOME 45+): the "Control input devices" permission prompt that appeared on every launch is gone. Wspr now uses the XDG RemoteDesktop portal via libei to inject text, so the compositor remembers the grant. You'll see a single "Started Remote Desktop" toast on first launch (or first paste of a session), then nothing afterwards. Wayland users on wlroots compositors (Sway, Hyprland) and X11 users are unchanged — the previous xdotool path remains as a fallback.
  • Linux settings window: widened and lengthened so that on Fedora KDE (and other systems with denser default fonts) the General tab fits without scrollbars and the About tab doesn't clip off the right edge.

5.1.1 — April 29, 2026

Fixed

  • Overlay transparency on macOS and Windows. The recording HUD pill was being rendered inside a white window background since v5.0.3 — a transparency setting had been accidentally gated to Linux only during a refactor. Restored to all three platforms.
