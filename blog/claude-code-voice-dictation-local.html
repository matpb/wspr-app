Claude Code Voice Mode Not Available? How to Dictate Locally Instead

Claude Code has a built-in /voice command, and for a lot of setups it simply is not there: API key logins, Bedrock, SSH sessions. It also sends your audio to Anthropic for transcription. Here is exactly what the documentation says, and how to dictate to Claude Code (or any other agent) with speech recognition that runs on your own machine.

If you typed /voice into Claude Code and got Unknown command: /voice or Voice mode requires a Claude.ai account, nothing is broken. You have hit one of the documented limits of the feature. This post goes through those limits using Anthropic’s own words, then shows the way around them.

Everything quoted below was checked against the Claude Code voice dictation documentation on November 18, 2026.

What the built-in voice mode does

The basics are simple and well done. You run /voice to turn dictation on, hold Space, talk, and release. The docs describe hold mode as “push-to-talk: recording runs while you hold the key and stops when you release it.” There is also a tap mode (/voice tap) where one press starts recording and a second press sends the prompt.

A few details worth knowing before you compare it with anything else:

  • Recording “stops automatically after 15 seconds of silence or two minutes total.”
  • It covers 20 dictation languages, and falls back to English when your configured language is not on the list.
  • It is tuned for developers: “your current project name and git branch name are added as recognition hints automatically.”
  • Transcription “does not consume Claude messages or tokens.”

Where it is not available

This is the section people land on this page for. The requirements list in the docs is short, and each line rules out a common setup.

Your setup Built-in voice mode What the docs say
Signed in with an Anthropic API key Not available The speech-to-text service “is not available when Claude Code is configured to use an Anthropic API key directly”
Amazon Bedrock, Google Cloud or Microsoft Foundry Not available Same sentence: not available with “Amazon Bedrock, Google Cloud’s Agent Platform, or Microsoft Foundry”
Claude Code running over SSH Not available “voice dictation does not work in cloud sessions or SSH sessions”
VS Code Remote, Dev Containers, Codespaces Not available “the microphone is on your local machine and the extension runs on the remote host”
WSL Needs WSLg “If WSLg is not available, for example on WSL1, run Claude Code in native Windows instead.”
Company-managed accounts Depends on your admin One documented error is “Voice mode is disabled by your organization’s policy”

The API key case catches people out the most, because the key does not have to be the way you meant to log in. From the troubleshooting section: if ANTHROPIC_API_KEY, ANTHROPIC_AUTH_TOKEN, an apiKeyHelper setting “or a third-party provider is in use, it takes precedence over a claude.ai sign-in.” An environment variable left over from another project is enough to make /voice disappear.

The SSH case is the one with no fix on Anthropic’s side. The agent runs on the server, the microphone is on your laptop, and the built-in recorder lives inside the agent.

Where your audio goes

Privacy

The documentation is direct about this: “Voice dictation streams your recorded audio to Anthropic’s servers for transcription. Audio is not processed locally.”

For many people that is a fine trade. Your prompt was going to Anthropic as text a second later anyway. It matters in two situations: when your network does not allow the connection (the troubleshooting list has entries for VPNs, proxies and TLS inspection), and when the things you say out loud are not all meant to become the prompt. A microphone picks up the colleague next to you and the half sentence you abandoned. With on-device transcription, the only thing that leaves your machine is the text you chose to send.

We wrote a longer breakdown of where dictation audio goes, app by app, if that is the part you care about.

The local alternative: dictate at the operating system level

Every limit in that table has the same cause: the recorder is part of Claude Code, so it inherits Claude Code’s login, its network path and the machine it runs on. Move dictation out of the agent and into your desktop, and none of that applies.

That is what Wspr does. It sits in your tray on macOS, Windows or Linux. You hold a global hotkey, talk, and release. Whisper transcribes the recording on your own GPU or CPU, and the text is pasted into whatever window has focus. Your terminal does not know or care where the text came from.

  • API key, Bedrock, any provider: Wspr never talks to your agent’s backend, so how the agent logs in is irrelevant.
  • SSH: the microphone, the transcription and the paste all happen on your local machine. The text arrives in your local terminal window, which sends it down the SSH session like anything else you type or paste.
  • Other agents: the same hotkey works in any terminal agent, in an editor chat panel, in a browser. You learn one habit, and it follows you between tools.
  • Long briefs: a proper task description is the point of dictating to an agent. Say everything you would say to a colleague.
Move dictation out of the agent and into your desktop, and the agent’s login stops mattering.

One detail matters for terminal interfaces in particular. Wspr puts the transcript on the clipboard and sends a single paste keystroke, then restores your clipboard. Tools that type the text one character at a time force a full-screen terminal UI to redraw on every character. We covered that problem, and the state of Wayland, in How to Dictate Prompts to Coding Agents on Linux.

Setup on macOS, Windows and Linux

  1. Download Wspr and start it. The first run downloads a Whisper model to your disk.
  2. Pick your hotkey in Settings. Choose one your terminal does not already use.
  3. Focus the terminal where Claude Code is waiting for input, whether it is local or an SSH session.
  4. Hold the hotkey, give the brief, release. The text lands at the prompt. Read it, then press Enter.

Three things make dictated prompts better for agents specifically:

  • Add your project’s words to the vocabulary list. Repository names, service names and internal libraries are the words a general speech model gets wrong. This is the manual version of what Claude Code does with your branch name.
  • Use a Large model for long briefs. Large v3 Turbo is a separate download in Settings and handles identifiers and file paths better than the small default.
  • Keep the paste-last shortcut handy. If focus was in the wrong window when you released the key, it re-inserts your last transcript where you are now.

On Linux, the hotkey and the paste go through desktop portals on Wayland, and what works depends on your compositor. The Linux page has the details.

When the built-in one is the better choice

If you sign in with a claude.ai account, work on your own machine, and only dictate to Claude Code, use /voice. It costs nothing extra, there is nothing to install, and the automatic project and branch hints are a real advantage for short prompts.

A separate dictation app earns its place when one of these is true: your login rules the built-in mode out, your agent runs somewhere your microphone is not, you would rather your audio stayed on your machine, or you want the same hotkey in every tool you use, not only one.
