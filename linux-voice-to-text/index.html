The state of dictation on Linux

Three rough options, none great.

If you've tried to set up dictation on Linux in the past, you know the story. The desktop ecosystem has always trailed macOS and Windows on accessibility tooling, and voice input has been the most glaring gap. The options have historically been: wrestle with half-abandoned open-source projects, run a cloud service that sends every word to someone else's server, or just give up and type.

In 2026, that's finally changing. Whisper-class models are small enough to run on consumer laptops, whisper.cpp has matured into a production-ready inference engine, and GPU acceleration is available on basically every modern Linux machine via Vulkan and CUDA. The pieces all exist, they just hadn't been packaged into a real desktop app. Now they have.

What's been missing is a packaged, installable desktop app that runs Whisper locally with GPU acceleration, has a proper UI, and Just Works on a modern Linux install. That's the gap Wspr is built to fill.

DIY open-source stacks

Tools like nerd-dictation, wtype scripts around whisper.cpp, or Vosk-based tools. These can work well for a tinkerer, but they're CLI-first, require manual setup per desktop environment, and don't give you a packaged app with a UI.

Cloud APIs

Like the OpenAI Whisper API or Google Speech-to-Text, wrapped in custom scripts. Accurate, but your audio leaves your machine and you pay per minute.

Desktop built-in accessibility tools

Useful for some workflows but typically limited in accuracy, languages, and customization.

Why Linux has been underserved

Three structural reasons.

Market size

Commercial dictation vendors (Dragon, Wispr Flow, Superwhisper, MacWhisper) build for Mac, Windows, and in some cases mobile, because that's where the paying users are. Linux is a rounding error on their revenue spreadsheet, so it stays unsupported.

Desktop fragmentation

GNOME, KDE Plasma, Hyprland, Sway, XFCE, Cinnamon: same kernel, six different ways to paste text into the focused window. Any serious Linux dictation tool has to handle X11 and Wayland, ibus and fcitx, xdotool and wtype. It's non-trivial and most vendors don't bother.

Audio stack churn

ALSA, PulseAudio, PipeWire: capturing microphone input on Linux has been a moving target for years. PipeWire finally stabilized that in 2023 to 2024, which is part of why this kind of app is feasible now.

What Wspr does on Linux

A native app. The same flow as everywhere.

Wspr is a native Linux app. It runs the same whisper.cpp engine as on macOS and Windows, with GPU acceleration where available and CPU fallback when it isn't.

Optionally trigger an AI rewrite: "make this a bullet list", "translate to French", "fix grammar". It is routed to OpenAI, Anthropic, or Gemini using your own API key.

Distro and desktop support

Session support, stated plainly.

Wspr ships as a Linux build for x86_64 systems. It's been validated on mainstream distros including Ubuntu and its derivatives. Other recent glibc-based distros should work too, though your mileage may vary depending on your desktop environment's input-injection behavior.

Wayland with the RemoteDesktop portal

Since version 5.1.2 Wspr injects text through libei via xdg-desktop-portal and holds one portal session for the life of the process, so the compositor remembers the grant and the old “Control input devices” prompt on every launch is gone.

The global dictation hotkey goes through the GlobalShortcuts portal on Wayland, which is why it still fires when no Wspr window is focused. Your desktop owns that binding, so you rebind it in your desktop's own settings (on GNOME, under Settings then Apps).

Privacy

The part Linux users care about.

A big reason people use Linux in the first place is because they don't want a vendor-controlled pipe between them and their computer. A dictation app that streams every word to a cloud service undoes that in one install.

Wspr never sends audio anywhere. The Whisper model lives on your disk, runs on your GPU, and produces text that's pasted directly into your focused application. No telemetry, no account, no cloud dependency for core transcription. AI rewriting is the only step that optionally calls out to a provider, and only the text you explicitly rewrite, using your own API key, routed directly from your machine to the provider you chose.

Performance

Pick the model your hardware likes.

Whisper "small" and "medium" models run comfortably in real-time on a mid-range Linux laptop with integrated graphics. On a discrete GPU, you can run "large-v3" and get near-instant transcription of multi-minute recordings. Wspr downloads models on first run; you pick the one that fits your hardware.

Does Wspr work on Wayland?

X11 sessions are fully supported and tested daily. Wayland sessions that expose the RemoteDesktop portal (KDE Plasma 6, GNOME 45+) are supported natively, through libei via xdg-desktop-portal. Compositors without that portal, meaning wlroots ones such as Sway and Hyprland, fall back to xdotool, which needs XWayland present. A bare Wayland session with neither the portal nor XWayland is not supported yet.
